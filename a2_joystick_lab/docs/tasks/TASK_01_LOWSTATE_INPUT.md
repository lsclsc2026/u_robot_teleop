# Task 01：原 A2 遥控器输入采集与解析延迟

## ① 实验背景

第一阶段需要确认工作台能否看到实体遥控器的按钮和摇杆输入，并评估 PC 端解析开销。原 A2 遥控器并不是普通 USB/HID 手柄，因此本实验通过 A2 Basic Service 发布的 DDS `rt/lowstate` 读取 `wireless_remote[40]`。实验只订阅状态，不发送任何运动指令。

## ② 实验流程

```text
原 A2 遥控器
→ A2 接收端 / Basic Service
→ DDS rt/lowstate
→ WSL2 工作台
→ 解析 wireless_remote[40]
→ 输出按钮、摇杆及 CSV 延迟数据
```

工作台有线地址设置为 `192.168.123.200/24`，通过 `eth1` 连接 A2 网络。分别进行了按钮/摇杆操作、无操作 baseline、A 键重复按压三组实验。

## ③ 实验结果

- `A/B/X/Y` 和四个摇杆轴均成功解析。
- 无操作实验收到 10606 帧，约 1.06 kHz。
- 到达间隔 p50/p95/p99：`0.920/1.586/5.264 ms`。
- 相对延迟 p50/p95/p99：`0.554/3.355/6.229 ms`。
- 解析耗时 p50/p95/p99：`0.060/0.189/0.288 μs`。
- A 键重复实验捕获到 12 次按下事件，解析耗时 p99 为 `0.240 μs`。

数据文件：`logs/no_touch_test.csv`、`logs/press_test.csv`、`logs/a_button_10x.csv`。

## ④ 分析

PC 端解析本身处于微秒以下，不是延迟瓶颈；主要抖动来自 DDS、WSL2、网络及系统调度。`relative_delay_ms` 是相对本次最佳样本的额外延迟，并不是“手指按下到 PC 收到”的绝对单向延迟。该实验完成了只读输入链路验证，但遥控器仍与 A2 配对，不能用于证明指令只经过 PC 转发。
